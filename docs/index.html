How it works

  1. Drop in the clip that will not play.
  2. Drop in any clip from the same camera, same settings, that does play. Cinesalve reads how your camera writes a file, so it can rebuild the damaged one to match.
  3. Watch the recovered footage. Save it when you are happy.

Nothing is uploaded. Your footage never leaves your Mac, there is no account, and the app works with the network switched off. Damaged recordings are often the only copy of something private, and they should not have to travel to a stranger’s server to be read.

How exact is the recovery

Exact, on everything measured so far, including footage written by real cameras. The test compares a repaired file against the original it was cut from and counts a frame as recovered only when it lands at the same position and the same size the camera wrote. A frame decoded from a repaired file is byte‑for‑byte identical to the same frame in the original.

What it does not do

On GoPro footage the sound is left out. These cameras write timecode and telemetry into the same block as the picture, and those bytes cannot be told apart from audio with enough confidence to place it correctly. Rather than write noise into your recording, Cinesalve recovers the video and says plainly that the audio did not survive. On simpler files, sound comes back with the picture.

Only GoPro hardware has been tested so far. DJI, Sony, Canon and iPhone recordings have not been through it yet. If you have a damaged clip from one of those, send it and you will get a straight answer about whether it can be recovered, before any money changes hands, and it will be added to the test suite.

It handles H.264 and HEVC video with AAC audio in MP4 and MOV containers, which is what consumer and prosumer cameras record. It does not handle ProRes, MXF or AVI. It repairs recordings that were interrupted, which is the common failure; it cannot invent footage that was never written to the card.
